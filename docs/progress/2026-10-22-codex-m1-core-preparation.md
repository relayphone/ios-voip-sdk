# M1 Swift core preparation

**Proposed:** this implements the Swift portion of M1 for integration. M1's push → ring → join → connected → hold → end and cold-launch native acceptances have not run here. The Expo bridge, launch-owned PushKit receiver and DEBUG provider monitor are separate changes.

**Measured:** the source-bound [receipt](../verification/2026-10-22-sdk-m1-core/receipt.json) records passing Swift 6 host tests, an arm64/x86_64 simulator Swift package build, an iOS 17.4 device module compile and a watchOS 10.4 source-compatibility compile. No simulator or device was created or used. Host tests exercise in-flight cross-source registration, event/server expiry boundaries, failed-registration retry, cold-launch pending policy, late attachment, replacement, cancellation before dispatch, nested cancellation observers, platform-settled expiry, exactly-once settlement, release of expired platform closures despite a hung handler, optional handlers, system-start metadata enrichment and wire roundtrip. A review regression first reproduced duplicate transport work during reentrant handler attachment, then passed after the delivery guard.

**Proposed behavior:** `ConversationClient.shared` owns the only manager and activates simulator support first. `configure` and the ownership-monitor callbacks run before first access. Snapshot membership and lifecycle follow the LCK manager; a synchronous metadata ledger supplies unavailable member, capability, mute, video, direction fallback and report timestamp fields. The read-only `CXCallObserver` supplies correlated call direction on iOS. A `.left` snapshot survives only while the manager lists that conversation; this adds no durable call history.

The MainActor handler coordinator retains actions until their actual `timeoutDate`, aborts cancelled/expired/replaced work, ignores stale results, and never fulfills an already-settled platform action. An attached handler requires join/start/end; omitted hold/mute/tones accept. A missing handler waits until the deadline, then uses configured fail/accept policy. Accept only applies if the platform still considers the action pending. Singular `pending` selects the earliest deadline, then action UUID. No-op mute/hold echoes are filtered only when no same-kind action remains pending.

**Proposed clarification:** event IDs are deduplicated inclusively through 120 seconds without refreshing their timestamps. Server IDs remain bound throughout active/in-flight lifetime and through 120 seconds from their first registration after removal, also without refresh. The RFC does not specify server expiry. Failed initial reports roll back registration so retries report rather than return a phantom UUID. Foreground duplicates return the prior UUID. Valid PushKit duplicates reattempt the incoming report with that UUID; only the documented CallKit already-existing UUID error for a known live conversation is accepted. Whether a required same-UUID re-report satisfies the real PushKit check remains unmeasured. An accepted re-report reactivates the server binding.

**Proposed clarification:** LCK merge/unmerge actions fulfill native topology work immediately because the RFC has no merge handler. No media/signaling merge work is invented. Outgoing metadata stays in a native ledger (`metadata(for:)`); no public conversation field is added. `connectedAt` comes from the transport's connected report; status still follows LCK state, including a joined state resulting from accepted signaling. M2 audio handling is deferred; M1 emits activation/deactivation only.

**Measured source review:** two isolated review axes caught retry poisoning, stale/reentrant delivery and placeholder metadata loss; the fixes have focused regressions. The LCK-only `@preconcurrency` import and delegate conformance retain the SDK's three async-manager concurrency warnings. Mutable state stays on MainActor and no unchecked Sendable conformance or unsafe alias was added. Device traces establish delegate main-thread behavior; future native acceptance still needs to verify integration timing.

No license file, upstream write, runtime lifecycle change or RFC comment was added by this component.
