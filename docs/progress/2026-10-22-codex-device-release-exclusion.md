# A0.2 / A6: device Release exclusion

**Measured local acceptance at `ad18324`:** the unsigned CocoaPods Release `iphoneos` example built and passed inspection. Its app, eight embedded native frameworks and SDK archive contain no direct CallKit load command or simulator/debug implementation symbols. The SDK declares no runtime resource bundle, and the actual app contains no simulator profile/runtime product. Six exported headers preprocess for Release `iphoneos` without simulator hooks or provider-creation monitor declarations. The [receipt and supporting bindings](../verification/2026-10-22-sdk-device-release/README.md) retain the exact source, artifact and log digests. This does not qualify China distribution approval or Apple's transitive LiveCommunicationKit dependencies.

Direction now uses the SDK's existing record: incoming reports register incoming metadata, app starts register outgoing metadata, and system starts enrich outgoing placeholders. The duplicate-incoming classifier compares the measured exact NSError domain/code and follows at most four underlying errors, without importing CallKit. The creation monitor is compiled only for Debug or iOS simulator; its Debug implementation uses an already available provider class and adds no CallKit import or linkage. **Open:** A7's Release foreign-provider event is a separate acceptance target; this change does not implement it.

The Swift package and pod embed the canonical behavior profile as a simulator-only Swift literal. Neither declares an SDK resource bundle, so there is no empty device resource bundle. A host control compares decoded values with `Sources/Engine/Resources/ios-27.0.json` and rejects drift. The standalone `cksim` build keeps its existing external profile. This supersedes M0's resource-bundle packaging choice, without changing the RFC's calling API. A2 integration must regenerate the literal when its canonical LCK deadline profile changes.

The public bridge is guarded for iOS simulators. `CKSimInjectPush` remains available there because the SwiftPM runtime's mailbox and example use it; `CKSimEmit` is also available there for the example's journal clock markers. Device preprocessing removes both. The Expo public header imports the public bridge directly. No extra example test header or internal module is required.

**Measured host controls:** core, push, projection and platform shim controls pass. The device gate controls compile actual unsigned iphoneos Mach-O fixtures: a clean executable passes; direct CallKit linkage and a compiled simulator hook fail. A guarded empty archive member passes, while the same archive carrying a real hook fails. Guarded simulator header declarations disappear during device preprocessing; unconditional leaks fail. The profile semantic drift and actual SwiftPM/CocoaPods declarations are checked. Host tests exercise the production Foundation error classifier, including wrapped duplicates and wrong domain/code/depth cases.

Its successful pod rebuild reused only this task's existing DerivedData, retaining the failed log, command and source receipt separately. An actual SwiftPM Release simulator build also passed through the public C module; five built object digests are retained. No app was launched for this acceptance.

The recipe binds committed inputs before and after the build, its exact command and log, executable/archive/header digests and successful inspection. Hosted qualification for this change is pending.
