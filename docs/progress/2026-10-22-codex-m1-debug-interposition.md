# M1 Debug monitor and simulator runtime cooperation

**Measured red:** the native capture at source `20c44f07a78ddf0748779dd5f289165f5e778f9e` passed Release M0 and all three Release M1 journeys, including the clock-bound expiry gate. Both Debug contract journals contained only `runtime.installed`. Their logs reported `CKSIM runtime refused: CXXPCProvider overrides initWithConfiguration:` after the Debug ownership monitor replaced the runtime's initializer implementation. The guard observed zero warnings and the accept case failed before it had a pending action. The private full capture is retained by the lead implementer; the [sanitized index](https://github.com/ziahamza/ios-voip-sdk/blob/addd1bf4a2d1abf90133fa6e6224f71f5271d5d4/docs/verification/2026-10-22-m1-debug-interposition/native-red-index.json) binds its files by SHA-256. This does not establish an accept-policy scheduling defect.

**Proposed fix:** after successful activation, SDK Debug iOS-simulator builds prepare a cooperative provider-creation source. The runtime's existing outermost initializer seam notifies it after concrete R2 verification and engine registration. The monitor reuses its synchronous owned-creation count and weak object-identity deduplication without replacing allocator or initializer IMPs. Observer invocation happens outside the runtime install lock; monitor registration holds no monitor lock. Repeated activation and monitor installation preserve the first diagnostic handler. No extra provider is allocated for the guard.

`VoIPPlatform` receives the registration closure from `SimulatorSupport`, so it has no dependency on the runtime. Device builds and initial activation refusal retain the genuine initializer monitor. Observer implementation and call sites are absent from Release simulator and device runtime objects; Release has no observer registration or notification work. The small simulator preparation method in the platform facade is a no-op in Release. All references to it from `SimulatorSupport` are guarded by Debug and iOS simulator, preserving the Release Engine-plus-SimulatorSupport bootstrap build without platform headers. R2's strict concrete-IMP checks are unchanged: arbitrary external wrappers still cause refusal.

**Measured preparation:** the [source-bound receipt](https://github.com/ziahamza/ios-voip-sdk/blob/addd1bf4a2d1abf90133fa6e6224f71f5271d5d4/docs/verification/2026-10-22-m1-debug-interposition/receipt.json) records 26 platform controls, including actual runtime observer helpers with the actual monitor, unchanged allocator/initializer IMPs, inactive registration refusal, owned/repeated/extra/background observations, and observer symbol exclusion. The new source seam initially failed the host build because the cooperative installation API was absent. Debug combined simulator Swift/Objective-C, separate SwiftPM runtime/SDK modules, Debug device, and the Release bootstrap module compile. The existing two distinct LCK concurrency warnings remain; no unsafe isolation aliases were added. Core, push, projection, push-context, M0, M1 and native-contract offline controls also pass. Independent specification and standards reviews found no actionable findings.
