# R5: bind the loaded image to the build identity

Acceptance target: the shipping identity gate compares bytes from the runtime image actually used by the probe with the run manifest and packaged runtime.

The probe resolves the defining image of `CKSimulatorEngine` through Objective-C runtime metadata. It hashes that image, its own executable and the profile beside that image. The gate compares all three digests with the manifest and independently hashes the packaged runtime/profile. Missing identity, duplicate identity and valid-format wrong digests fail. The focused native acceptance runs these checks before the longer journeys.

## Evidence

- **Measured red:** the old `shipping_journal` check accepted a synthetic valid-format wrong loaded-image digest in a measured shipping capture from [green hosted run 39680771297](https://github.com/ziahamza/ios-voip-sdk/actions/runs/39680771297). This isolated the identity check from the separately fixed R1 threading defect in that capture.
- **Measured controls:** eleven Python controls pass, covering a synthetic positive, missing/wrong loaded runtime/probe/profile digests, missing/duplicate identity and tampered packaged runtime/profile bytes.
- **Measured native green:** the focused iOS 27.0 simulator capture passes actual loaded-image, executable and profile comparisons with manifest/package bytes; all four incoming callback queue checks still pass. Receipt hashes bind the recorded console and journal. The run-owned simulator was deleted.
- **Measured review:** independent standards and specification reviews found no actionable issues. Swift typecheck, existing adversarial harness, Python/shell syntax and diff checks pass.

[Native evidence and the red-control record](../verification/2026-10-22-runtime-r5/) are committed without binary artifacts. The local build records its base commit and dirty source-input identity; fresh hosted CI remains required on the final integrated commit. R6's broader shipping semantics controls and R9 release attestation remain separate work.
