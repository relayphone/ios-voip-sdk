# R5: bind the loaded image to the build identity

Acceptance target: the shipping identity gate compares bytes from the runtime image actually used by the probe with the run manifest and packaged runtime.

The probe resolves the defining image of `CKSimulatorEngine` through Objective-C runtime metadata. It hashes that image, its own executable and the profile beside that image. The gate compares all three digests with the manifest and independently hashes the packaged runtime/profile. Fresh receipt captures always enter the shipping gate, so a missing or unknown identity cannot silently select historical validation. Missing identity, duplicate identity and valid-format wrong digests fail. Explicit `--allow-legacy --require-receipts` retains receipt checks for the pre-shipping fixtures. The focused native acceptance runs the digest checks before the longer journeys.

This isolated the identity check from the separately fixed R1 threading defect in that capture.
- **Measured controls:** eleven Python controls pass, covering a synthetic positive, missing/wrong loaded runtime/probe/profile digests, missing/duplicate identity and tampered packaged runtime/profile bytes.

The default now rejects them; controls also bind a manifest and prove that removing the identity or setting an unknown version reaches an identity rejection. All 52 adversarial harness checks pass, including explicit historical replay with receipts. This is a synthetic regression measurement, not a new simulator run.
- **Measured native green:** the focused iOS 27.0 simulator capture passes actual loaded-image, executable and profile comparisons with manifest/package bytes; all four incoming callback queue checks still pass. Receipt hashes bind the recorded console and journal. The run-owned simulator was deleted.
