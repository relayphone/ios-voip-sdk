# R2: concrete ABI guards

**Measured by final native acceptance:** install verifies all 22 CallKit hooks on the resolved concrete provider, controller, observer and supported action classes. Provider and controller initialization uses separate public and concrete original implementations, correct retained/consumed ARC conventions and outermost-only registration. The action hierarchy captures original implementations before mutation and hooks every covered superclass so original-to-super forwarding runs once.

The snapshot preflight toggles and reads back all four KVC keys and catches Objective-C exceptions. Unsupported selectors and snapshot failures retain inactive report/request guards: a diagnostic `CKSimRuntimeErrorDomain` error, empty snapshots and inert mutators. They never restore genuine report/request methods after refusal. Shadow mode refuses differing concrete incoming/delegate originals before binding. PushKit's three hooks also preflight and verify their concrete implementations.

That passing capture predates the final action-superclass forwarding fix and does not qualify it. The final candidate compiles for arm64 and x86_64; both fault controls are absent from shipping builds. Standards and Spec reviews are clean after addressing their forwarding and missing-selector-test findings.

**Measured:** the frozen final candidate passes all eight cases and 18 checks per case (144 total). ## PR review follow-up

**Measured red:** the review probe reproduced four wrong-queue callbacks after activation refusal: incoming reports on a custom provider delegate queue and all three controller request entry points. The nil-provider-queue case remained on main.

**Measured by the [13-case native follow-up](https://github.com/ziahamza/ios-voip-sdk/blob/addd1bf4a2d1abf90133fa6e6224f71f5271d5d4/docs/verification/2026-10-22-runtime-r2/review-green-13-cases/summary.json), all 243 checks pass:** refusal now keeps weak-key callback-queue metadata independently of the Swift engine. Initializer originals are captured before validation and preserved when validation lookup fails; wrappers always call that genuine initializer, never return an uninitialized receiver. PushKit rejects differing concrete implementations of either setter before mutating its three hooks. The five added cases cover the queue regression, both initializer lookup faults with initialized-object state after an autorelease-pool drain, and both PushKit setter overrides. The owned simulator was deleted. Both review axes found no new confirmed issue; the source builds for arm64 and x86_64 with all three fault controls absent from shipping bytes.

**Supported ABI boundary:** the advertised public provider/controller constructors must exist in Apple's ABI. If a real public constructor Method is absent, preflight refuses before allocating its sample and does not install an initializer wrapper without a genuine original. This does not replace an unavailable public API or qualify a hypothetical root-absent/concrete-present hierarchy. The test lookup faults preserve genuine constructors and do not simulate structural API removal. A separate, bounded experiment forced allocation to return nil: Objective-C observed nil, while Swift's nonoptional constructor returned and its description bridged to an empty string. That result does not produce a valid native object, so no allocation workaround is shipped. SDK source activation failure continues to follow M0's rollback/log/proceed-genuine policy.

## Hosted supervisor qualification follow-up

**Measured:** hosted attempts passed native ABI behavior assertions but could not bind a successful launcher receipt. Inspection of 15 hosted traces showed that the launcher PID header follows the terminal marker; requiring it before stopping was an incorrect assumption. The corrected supervisor stops the completed owned app, drains launcher output, then requires one matching PID. Its real two-process buffered-header regression failed before the correction and passes afterward; all 57 focused harness checks pass. Primary termination failures remain visible independently of identity failures. See [the bound supervisor evidence](https://github.com/ziahamza/ios-voip-sdk/blob/addd1bf4a2d1abf90133fa6e6224f71f5271d5d4/docs/verification/2026-10-22-launch-receipt/README.md).

**Proposed, pending hosted native execution:** the short ABI scenarios now wait for their UIKit scene to become active before running. The ABI step runs before the long journey suite so its native verdict is available sooner. This fixture readiness change compiles locally; it is not evidence that the hosted termination timeout is fixed.
