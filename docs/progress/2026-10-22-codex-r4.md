# R4: loader recovery and test-host loading (October 22, 2026)

## Acceptance target

Apps without the SDK use process-local test-host injection by default. A saved
simulator-wide installation can be repaired after deleting its runtime package,
without discarding another injector's changes. This prepares START-HERE §4.A R4;
the offline check is integrated into CI; an owned simulator acceptance remains
pending before a PR is accepted.

## Prepared change

- `cksim repair` reads the existing ownership file independently of the runtime
  package. It removes the exact saved loader entry from `DYLD_INSERT_LIBRARIES`,
  preserves unrelated entries, and restores recognized `CKSIM_*` values.
- All keys are checked before writes. Ambiguous external values and extra exact
  loader duplicates refuse with the affected key and ownership-file path.
- Failed installs and failed repairs retain recovery state. Successful repair
  deletes that state; repeating it is a no-op. `repair` and `uninstall` do not
  require `--bundle`. Every CLI `simctl` subprocess has a 60-second deadline.
- The runtime documentation makes generated `.xctestrun` host environments the
  default and distinguishes a UI-test runner from its app under test. Global
  `install` remains an explicit option with deletion and recovery instructions.

## Proposed native acceptance

On a new run-owned simulator, measure install with another library
present, delete the package, append another unrelated entry, repair via the source
CLI, and confirm those entries remain while owned keys return to their original
values. Relaunch the probe through a test-host-only configuration to bind the
documented default to a fresh native result. Native loader behavior and timeout
execution were not measured by the offline fake-simctl suite.

This changes no SDK API and requires no RFC deviation.
