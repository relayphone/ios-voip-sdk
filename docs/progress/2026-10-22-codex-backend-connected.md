# A8: signaling acceptance precedes backend connection

**Proposed behavior:** fulfilling incoming Join accepts signaling. A joined platform conversation projects as `connecting` until the application reports `.connected`; that report supplies `connectedAt`. An outgoing fulfilled Start may remain `dialing` until the transport reports progress. Platform hold, leaving and terminal states retain precedence. The production change is one projection line; the public API shape is unchanged.

The M0 example, M1 journey and cold-launch journey now observe settled `connecting` without a timestamp before issuing their explicit fixture backend-connected report. The manual example enables Report connected for settled connecting/dialing calls. The native no-handler accept fixture observes signaling settlement at the policy deadline, then reports fixture backend connection. Its gate keeps native LCK answer/connected timing independent: the framework's joined state can precede that report. Updated existing gates bind the conversation, marker order and connected timestamp, and reject premature connection or missing timestamps. Demonstration signaling remains a fixture; no real media connection is implied.
