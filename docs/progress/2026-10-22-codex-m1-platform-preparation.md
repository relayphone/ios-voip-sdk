# M1 platform shims: preparation

**Proposed:** these shims are part of M1's native client. This preparation does not qualify the M1 push journey, real APNs, or a second genuine LCK manager. Package/pod wiring and the Swift push policy belong to the integrated M1 change.

`Sources/VoIPPlatform` provides one strongly retained native `PushRegistryOwner` and `PushReceiver`. Create the receiver on main during app launch, then call `start()` before waiting for a UI scene or JavaScript. A different receiver cannot replace the process owner. Registration sets the main-queue registry's delegate before its desired push type. Tokens are forwarded as bytes and never logged. The shim forwards dictionaries without parsing or deciding invitation policy.

The new callback is exactly `pushRegistry:didReceiveIncomingVoIPPushWithPayload:metadata:withCompletionHandler:`. Its definition is conditional on the metadata header and its access is guarded for iOS/watchOS 26.4. The legacy callback forwards `mustReport = true`. Native receivers settle the supplied completion after their reporting work; a lock ensures repeated or concurrent settlements call the system completion once on main. The completion retains its native receiver through settlement.

`ProviderCreationMonitor` is a DEBUG diagnostic aid for D13. Install after simulator activation and immediately bracket creation of the SDK's sole manager. It wraps the public provider initializer and the provider metaclass's public allocator, preserving the saved implementation and ARC ownership conventions. A real allocation reveals its concrete class without allocating a probe. Initializer overrides along that class's superclass chain are wrapped before its caller initializes it. Nested concrete/super calls and placeholder replacement produce one diagnostic per final object; a weak pointer-identity set does not retain providers. No `NSObject` method is replaced. Unsupported ABI or read-back failures diagnose and preserve ordinary initialization. Release builds contain no monitor hook implementation or CallKit reference.

**Coverage limit:** this is not a public `ConversationManager` creation observer. Allocator paths that bypass the monitored public provider allocation/initialization may be missed. An owned bracket that observes no provider diagnoses that lack of coverage. Creation on another thread during the bracket does not count as the owned manager's provider. Native qualification must establish that the supported framework version takes the observed path; the synthetic class-cluster control alone does not establish that fact.

**Measured:** `python3 discovery/check_platform_shims.py` passes 21 host/compiler controls on Xcode 27.1. Ten host controls exercise completion races/receiver lifetime, initializer behavior and balanced ARC, class-cluster/super chaining, inherited intermediate overrides, initializer-time placeholder replacement, duplicate owned creation, background creation, nil initialization, unsupported ABI, and an unrelated allocator result whose methods remain untouched. The source compiles in Debug and Release for iOS 17.4 simulator/device and watchOS 10.4. Swift 6 strict-concurrency checks import and implement the main-actor receiver API on those targets. `nm` checks show the two Release device monitor objects contain no hook implementation, runtime method replacement, or `CXProvider` references. The run, compiler version and source hashes are in [the evidence record](../verification/2026-10-22-m1-platform/checks.json).

Independent spec review found two gaps in the first preparation: an intermediate initializer could bypass the root, and initializer-time substitution could count one final provider twice. Both regression controls fail against the initial commit: [inherited override](../verification/2026-10-22-m1-platform/inherited-cluster-red.json), [placeholder replacement](../verification/2026-10-22-m1-platform/init-substitution-red.json). Both pass after the corrections above. These are synthetic host measurements, not claims about a new device behavior.

Independent spec and standards review each reported no remaining actionable findings after rereading the corrections and the unrelated-allocation guard. Reviewers performed no native execution.

No device, simulator, push registration or app launch was performed for this preparation.
