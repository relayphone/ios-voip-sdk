# R1: incoming-report completion queues

Acceptance target: incoming-report completions use main when the provider's delegate queue is nil, including duplicate-report errors; explicit delegate queues remain honored.

## Change

The runtime's nil-queue fallback is now `.main`. The unused private report-completion queue was removed. Both existing main-thread conformance checks now include `report.incomingCompleted`.

The focused `report-threading` probe records thread and queue identity inside four actual callbacks: nil/custom queue, each with a successful and duplicate report. It runs in the normal CI harness and can run alone:

```sh
CKSIM_ONLY=report-threading bash discovery/run.sh
```

## Evidence

- **Measured device reference:** all 19 incoming completions in the four committed `2026-10-20-iphone13-ios27-*.jsonl` traces have `main: true`.
- **Measured regression:** the new off-main success/duplicate fixture mutations exposed the old gate's false pass. Both are now rejected by `discovery/check_harness.py`.
- **Measured native red:** the unchanged engine completed the focused scenario, but both nil-queue callbacks had `main: false`; custom callbacks retained their queue. The semantic checker failed with `nil queue incoming completion delivered off main`.
- **Measured native green:** all four callbacks pass against the queue fix on the iOS 27.0 simulator: both nil-queue callbacks are main, and both custom callbacks retain their queue. The current runtime source-input digest matches the captured build identity.

An initial green attempt timed out during simulator installation before app entry. A later run's launcher was interrupted; its already-built probe was resumed on the same run-owned simulator with a fresh run ID. The successful receipt records the resumed launch. Both completed scenarios reached `done`, and their simulators were deleted. No simulator-wide environment changes were made.

Native traces, process receipts, journals and manifests are in [the R1 evidence directory](../verification/2026-10-22-runtime-r1/). Local native builds record their base commit and dirty source-input digest; hosted CI supplies validation of the committed revision. This acceptance does not address R2 or R5–R9.
