# M1 terminal projection and incoming report serialization

**Measured red:** the immutable native capture at source `83e396bac6b9c3465b17320cc80ba7088bf53ca4` contains seven completed, successful process receipts, but the strict M0 semantic gate fails with `missing LCK state left`. The [sanitized index](https://github.com/ziahamza/ios-voip-sdk/blob/addd1bf4a2d1abf90133fa6e6224f71f5271d5d4/docs/verification/2026-10-22-m1-terminal-projection/native-red-index.json) binds its manifest, build receipt, summary and individual process/trace receipts. Root retains the full capture unchanged. No gate or fixture state is weakened by this change.

**Proposed fix:** `conversationChanged(.left)` supplies authoritative system state even when `manager.conversations` is already empty. The client buffers that actual delegate object, preserves its metadata, cancels pending actions without intermediate refresh erasing the record, and publishes `.ended`. The buffer survives the rest of the current actor turn. A queued cleanup removes it once the manager no longer lists it; this creates no durable call history. Snapshot lookup and refresh both consult the terminal buffer.

Object identity is checked before publication, metadata mutation or action cancellation. A stale terminal callback for an older object cannot affect a new manager object that reuses its UUID. Cleanup also carries a fresh generation, so an older cleanup cannot erase a newer terminal publication. Ordinary disappeared-record pruning waits one actor hop, and cancels before deleting metadata so a synchronous terminal callback can still publish the known end reason. Unknown late terminal callbacks use the existing minimal placeholder model without inventing end metadata. The previously filtered post-end mute echo remains filtered during the terminal turn.

**Proposed report invariant:** every actual incoming report is serialized behind the previous attempt for the same UUID. Each attempt retains the caller's TaskLocal push identity. The report Task itself performs generation-checked queue cleanup before caller continuations resume; callers cannot remove a newer queued attempt, and no loop waits for another continuation to clear an already-completed Task. Metadata is registered synchronously before queueing. A successful predecessor carries reported history to its successors; failed initial attempts can still roll back registration, while successful ended-call tombstones remain intentional.

Foreground duplicates keep their fast return/await behavior and never bind or report again. Every PushKit invocation still retains its own actual report attempt. The unified actual LCK call binds `SimulatorSupport.associateIncomingReport(id)` immediately before reporting, with a scoped `finishIncomingReport(id)` defer. These calls compile only for the iOS simulator. The separately reviewed platform helper removes only the current UUID+TaskLocal push identifier, including an attempt rejected before the lower-level hook. This is an invariant guard; it does not claim an additional native failure was measured.

Projection controls cover terminal object visibility, removal without history, replacement identities, obsolete side-effect rejection, cleanup generations, per-UUID FIFO execution, distinct inherited TaskLocal identities, successor cleanup protection and report-failure history. Three independent read-only reviews supplied the spec/standards axes; the stale-terminal cancellation finding was fixed and rechecked. Only the existing LCK async-manager compatibility warning remains.
