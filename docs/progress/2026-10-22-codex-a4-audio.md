# A4 / A0.3: call-time audio ownership

Status: proposed implementation with measured host/compiler checks. Native media journeys and real iPhone interruption delivery remain pending. This branch starts from M2 `ee16309` and merges A2 `43a6954`; A0/A1/A7/A8 must be integrated before new milestone acceptance.

The shared C serial dispatch queue backs a Swift custom serial executor. Session configuration, route reads/selections, the selected React Native WebRTC/LiveKit bindings and the optional Swift LiveKit adapter use that queue. Main callbacks update scalar authorization and enqueue work. The SDK never calls `AVAudioSession.setActive`.

A real start/join action starts mandatory preparation before handler delivery. Preparation configures category/mode and backend ownership at call time. Its cancellation permit crosses queued native blocks, and is checked before backend lookup or writes. WebRTC holds its configuration lock around one synchronous configuration/gating block, including error/exception unlock. LiveKit disables automatic session ownership and gates availability before the handler can request capture. An already authorized call keeps its engine when another call prepares. Idle launch/registry attachment performs no category, manual-audio or engine-availability writes.

A2's effective deadline is unchanged. Prepared no-handler actions can use the configured accept policy at that deadline; unfinished or failed mandatory preparation fails safely. A blocking framework setter already executing cannot be preempted. Its eventual return cannot revive a canceled action, but a permanently blocked setter also blocks later work on this deliberately serial audio queue. The independent activation watchdog retains its existing proposed 10-second absence plus 5-second recovery policy.

The typed Objective-C lifecycle observer compiles the new iOS/watchOS 27 notifications only with headers that declare them. Older SDK builds compile the legacy interruption path. Runtime availability selects the new active/inactive/resumption notifications on 27+, and legacy interruption begin/end on older systems. Both paths project immutable scalar observations onto the SDK actor. Inactive/reset observations revoke engine authorization; a resumption recommendation cannot enable audio. Only a genuine LCK activation restores authorization. Route observations use a 200 ms debounce; no route or fold behavior is inferred from a device model.

Event delivery now carries `ConversationEventContext`. Watchdog events identify each actual affected conversation; global session, provider reset and ownership events omit the ID. The Expo bridge includes `conversationId` only when present. The explicit media adapter argument on application start and the guarded post-publication `finishLaunch` seam are preparation for A7's sole-owner integration, which removes legacy construction/registration paths.

The M2 fixture now requests media inside the prepared join handler. Its initial observation does not require launch-time category/gating. It must observe gated capture demand before fulfilling, then explicit backend-connected reporting before connected media stages. That strict connecting projection depends on A8; the old M2 native receipts remain historical and do not qualify this change.

The native stale-audio gate bounds liveness from the observed pre-fulfillment media demand through scoped missing/recovery/end events. Public `connected` now follows a backend report, so its timestamp cannot identify the actual watchdog start. Exact 10+5 policy boundaries are covered by production-source host controls; native liveness does not measure the exact start-to-fire duration.
