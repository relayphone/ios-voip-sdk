# M0: shared-source package and Expo bootstrap

**Implemented, native acceptance pending:** one Swift source tree is exposed through `Package.swift` and the Apple-only Expo module. The source target choice follows START-HERE: simulator implementation is compiled behind platform guards, and device code has a no-op activation facade. No XCFramework is distributed. Activation prepares the engine before mutating frameworks and restores genuine implementations if preparation or verification fails. The example activates before creating its LCK manager.

**Measured preparation:** [core bootstrap preparation](2026-10-22-codex-m0-bootstrap.md), [Expo preparation](2026-10-22-codex-m0-expo-preparation.md), and [acceptance tooling](2026-10-22-codex-m0-acceptance-preparation.md) record compilation, offline controls and review limits. These do not establish a native call journey.

**Pending acceptance:** a Release Expo build with bundled JavaScript must report an incoming conversation, retain it ringing, join and end in a fresh simulator without runtime injection. Healthy, bad-profile and post-install PushKit refusal bootstrap cases must run in the same owned simulator. Device final-link and SwiftPM object inspection must show no simulator implementation. Both local and CI receipts must bind the source before build, exact products, process identities, logs and cleanup. The first local Expo build was interrupted during host slowdown; it is not a successful build or compiler failure.

The runtime is still version 0.1.1 proposed; R3 remains deferred. The example-only manager and controls are fixtures for M0. The SDK-owned process manager, RFC client API, PushKit and TypeScript hooks are M1. Default-calling-app entry points are M3. No license file is added.
