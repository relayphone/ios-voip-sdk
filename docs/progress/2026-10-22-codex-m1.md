# M1: conversations, handler, PushKit and Expo API

**Implemented, acceptance in progress:** the SDK owns one LCK manager, projects state and native pending actions, runs handlers against actual LCK deadlines with cancellation/reload guards, and exposes commands/reports plus revisioned TypeScript state/hooks. App metadata is registered before incoming reporting. The native metadata/legacy PushKit shim registers during launch; valid and required invitations report, malformed optional invitations skip, and two-minute event/server deduplication reuses conversation identity. Token values are never logged.

**Measured local Release green:** [b17c50b receipts](../verification/2026-10-22-sdk-m1/release-journeys-b17c50b/README.md) bind the full push journey, cold native pending action before JS, later handler attachment, default no-handler expiry, M0 prerequisites and device exclusion. The earlier [83e396b red](../verification/2026-10-22-sdk-m1/native-red-83e396b/README.md) led to real terminal-object projection and async push correlation fixes.

**Measured stronger gate at 20c44f0:** all three Release M1 cases also passed with native failed-answer settlement bound to the actual pending deadline through a synchronous clock marker. The additional Debug native contracts then exposed a monitor/runtime hook conflict: the creation monitor replaced the runtime’s verified concrete initializer, triggering safe runtime refusal and genuine restoration. The [red receipt](../verification/2026-10-22-sdk-m1/debug-contract-red-20c44f0/receipt.json) binds that failure. Neither Debug ownership nor accept-policy timing is qualified by that run; accept never reached a pending action. A cooperative Debug creation observer is being implemented without relaxing R2 checks.

**Remaining acceptance:** pass the full Release and Debug contract runner at the integrated source, then current-head hosted CI. Native real-APNs measurements follow on the dedicated test iPhone: locked cold launch/answer-to-activation, mustReport during a conversation, and LCK satisfying PushKit’s cold reporting requirement. Those device facts are unmeasured for this SDK. M2 media and M3 entry points are separate milestones. No R3 teardown behavior is invented.
